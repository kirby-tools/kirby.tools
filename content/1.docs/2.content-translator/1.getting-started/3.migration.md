## Migrating to v3.15 (Rejection Results)

**No breaking changes**, four notable ones:

- [`translateContent()`](/docs/content-translator/php-classes/translator#translatecontent) returns a `ContentTranslationResult` instead of `void` – counts plus a rejection per dropped unit, each naming its field.
- A custom [`Strategy`](/docs/content-translator/php-classes/strategies#implementing-a-custom-strategy) returns `null` for a unit it could not translate. The previously documented pattern – pre-filling the result with source text – still works but makes drops invisible to the new result; switch to `null` slots. A `null` slot means the strategy owns the [`translate:warning`](/docs/content-translator/advanced/hooks#content-translatortranslatewarning) hook for that unit, since it is the only layer that knows the reason.
- A rejected title or slug translation no longer writes the source title into the target language. A manually translated title survives a failed run.
- DeepL requests for text whose only markup is a [KirbyTag link](/docs/content-translator/advanced/kirbytags) go out without HTML tag handling, which used to entity-escape the surrounding text (`s&#x27;ouvre`) and shift the whitespace around the link. A [`tag_handling` you configured yourself](/docs/content-translator/php-classes/deepl-client) is respected unchanged.

## Migrating to v3.14 (Drop Reasons)

The reasons the [`translate:warning`](/docs/content-translator/advanced/hooks#drop-reasons) hook reports were renamed. A handler matching the old strings stops matching.

| Before                            | After                                         |
| --------------------------------- | --------------------------------------------- |
| `placeholder count mismatch`      | `placeholder mismatch`                        |
| `empty or non-string translation` | `empty translation`, `non-string translation` |

`missing translation` is new. A strategy returning fewer entries than it was given units used to be dropped silently.

For custom strategies, an empty string is now a failed unit rather than a translation, so the field keeps its source text instead of being blanked.

## Migrating to v3.11 (Strategy Refactor)

v3.11 introduces a typed `Strategy` interface and a unified `strategy` config option. **No breaking changes** – existing code keeps working unchanged. Two deprecations to watch for v4:

::warning

- `johannschopplich.content-translator.translateFn` – migrate to `'strategy' => $closure`. Signature is identical.
- `JohannSchopplich\ContentTranslator\KirbyText::translateText()` – migrate to `Translator::translateText()`. Same routing, same result.

::

### `translateFn` → `strategy`

```diff [config.php]
 return [
     'johannschopplich.content-translator' => [
-        'translateFn' => function (string $text, string $target, ?string $source) { /* … */ },
+        'strategy' => function (string $text, string $target, ?string $source) { /* … */ },
     ],
 ];
```

When both keys are set, `strategy` wins.

### `KirbyText::translateText()` → `Translator::translateText()`

```diff
-use JohannSchopplich\ContentTranslator\KirbyText;
-$translated = KirbyText::translateText($text, 'de', 'en', $kirbyTags);
+use JohannSchopplich\ContentTranslator\Translator;
+$translated = Translator::translateText($text, 'de', 'en');
```

The new pipeline routes through the configured strategy and handles KirbyTags structurally without per-call configuration.
