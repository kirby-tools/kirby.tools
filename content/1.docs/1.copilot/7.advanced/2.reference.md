### Prompt History

Your prompts are saved in the browser's local storage (up to 50 entries per site). Access recent prompts via the history dropdown or navigate with arrow keys in the prompt textarea.

| Action          | Shortcut                                      |
| --------------- | --------------------------------------------- |
| Previous prompt | :kbd{value="↑"} (when cursor is at the start) |
| Next prompt     | :kbd{value="↓"} (when cursor is at the end)   |

## Placeholder Syntax

A placeholder is a field name wrapped in curly braces. When the prompt is sent, each placeholder is resolved with the actual field value from the current model (page, file, or site).

```
Summarize "{title}" in a meta description (max 155 characters). Include the main benefit and end with a subtle call-to-action. No quotes. This is the page:
{content}
```

## Page Reference Syntax

Reference other Kirby pages in your prompt with `@page://page-id`. The referenced page's content is fetched and appended to your prompt automatically.

```
Compare these two products:
@page://products/basic
@page://products/pro
```

## Supported Field Types

Kirby Copilot can generate content for all built-in Kirby field types, with the following exceptions:

- `pages`, `files`, `users` – Relation fields
- `gap`, `headline`, `hidden`, `info`, `line` – Blueprint fields without user input

A plugin's field type that extends a core field is written like that field. Copilot in the Panel and agents skip any other plugin field type until a plugin maps it to a core type. Any plugin can, including a small one of your own for another vendor's field:

```php [site/plugins/copilot-field-types/index.php]
Kirby::plugin('acme/copilot-field-types', [
    'johannschopplich.copilot' => ['fieldTypes' => ['rating' => 'number']]
]);
```

The `rating` field is then written like a `number` field, by agents and by Copilot in the Panel.
