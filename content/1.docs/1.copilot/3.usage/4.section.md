---
title: Copilot Field
description: Single-field generation with locked prompts and auto file context, for image alt text, captions, and editorial workflows.
---

The Copilot field provides a dedicated interface for generating content for another field of the same blueprint. Unlike the [Panel view button](/docs/copilot/usage/view-button) which targets multiple fields at once, the Copilot field focuses on a single field with additional features: persistent prompts saved between sessions, immutable prompts for locked workflows, and automatic file context on file pages.

::tip{icon="i-ri-image-line"}
**File Pages**: Use `files: auto` to include the current image as context, for alt text, captions, or descriptions.
::

## Basic Setup

Add a Copilot field to any blueprint by specifying the target field:

```yaml [pages/default.yml]
fields:
  blocks:
    label: Content
    type: blocks

  copilot:
    type: copilot
    field: blocks
```

The Panel will display a collapsible Copilot interface below your fields:

Click on the arrow to expand the accordion and enter your prompt. While a generation runs, the **Generate** button reports progress and a **Stop** button appears next to it:

## Prompts and Undo

### Reset Prompt

If you've modified a predefined prompt, click the **Reset** button (circular arrow icon) to restore the original.

### Undo Generation

After generating content, an **Undo** button appears to revert to the previous content.

### Dynamic Prompts With KQL

A [Kirby query](/docs/copilot/configuration/local#userprompt) in `userPrompt` or `systemPrompt` lets content editors define their own prompt in a dedicated field:

```yaml
fields:
  copilot:
    type: copilot
    field: blocks
    userPrompt: "{{ page.customPrompt.value }}"
```

## Configuration Reference

The Copilot field takes every [view button property](/docs/copilot/configuration/local#view-button-properties), plus the following:

::callout{icon="i-ri-keyboard-line" color="info" to="/docs/copilot/advanced/reference#keyboard-shortcuts"}
See the **Quick Reference** for all keyboard shortcuts.
::

### `field` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

**Required.** Specifies which field to generate content for. This should be the name of a field defined in the same blueprint.

The Copilot field works only among the top-level fields of a blueprint. Inside a blocks, layout, structure, or object field, it shows an error instead.

```yaml
fields:
  copilot:
    type: copilot
    field: blocks
```

### `editable` :u-badge{label="Boolean" class="align-middle ml-2 rounded-full!" variant="subtle"}

Control whether users can edit the prompt. Setting it to `false` is useful if a specific `userPrompt` should always be used without modifications.

**Default:** `true`

```yaml
fields:
  copilot:
    type: copilot
    field: content
    userPrompt: Write a technical guide about "{title}". Include an introduction, step-by-step instructions, and a summary.
    editable: false
```

### `files` :u-badge{label="Boolean | String" class="align-middle ml-2 rounded-full!" variant="subtle"}

This property enables file attachments for providing context to the AI model.

**Default:** `true`  
**Options:** `true`, `false`, `"auto"`

To disable file attachments and prevent users from adding files, set the `files` property to `false`:

```yaml
fields:
  copilot:
    type: copilot
    field: blocks
    files: false
```

:::panel-mock
::panel-copilot-field
---
files: false
---
::
:::

On a Kirby file page, setting `files: auto` pre-selects the **current file as context** for the user prompt. This is useful for generating metadata like alternative text based on the image that has already been uploaded to the Panel:

```yaml [files/image.yml]
columns:
  - width: 2/3
    fields:
      alt:
        label: Alternative Text
        type: text

  - width: 1/3
    fields:
      copilot:
        type: copilot
        field: alt
        # Use the uploaded file as context
        files: auto
        # Optional: Provide a predefined user prompt
        userPrompt: Describe this image for alternative text. Include key features, colors, and context. Max 125 characters.
        # Optional: Disable the editing of the user prompt
        editable: false
```

The Copilot field above will use the current file of a Kirby file model as context for the user prompt:

![Copilot field with generated image alt text](/img/kirby-copilot-files-auto.png)

Only images are attached this way – `gif`, `jpeg`, `png`, and `webp`. On a file of any other type, including PDF, the Copilot field shows a note that the type is not supported as context. Unlike `files: true`, `auto` does not add the file picker, so the user cannot attach a different file instead.

::tip
Learn more about working with files on the dedicated [File Attachments](/docs/copilot/prompt-dialog/files) page.
::

### `open` :u-badge{label="Boolean" class="align-middle ml-2 rounded-full!" variant="subtle"}

Set the initial state of the prompt input accordion.

**Default:** `false` (closed)

```yaml
fields:
  copilot:
    type: copilot
    field: content
    open: true
```

### `storage` :u-badge{label="Boolean" class="align-middle ml-2 rounded-full!" variant="subtle"}

Enable or disable local storage for saving user prompts in the browser. When enabled, prompts are remembered between sessions. The storage is keyed by the Panel view and the target field, so the same Copilot field keeps its prompt per page – and two Copilot fields writing to the same field on the same page share one entry.

**Default:** `true`

```yaml
fields:
  copilot:
    type: copilot
    field: content
    storage: false
```

### `size` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

Controls the size of the **Generate**, **Stop**, and **Undo** buttons in the Copilot field.

**Default:** `md`  
**Options:** `xs`, `sm`, `md`, `lg`

```yaml
fields:
  copilot:
    type: copilot
    field: content
    size: lg
```

### `help` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

Provide additional help text or instructions for the Copilot field.

```yaml
fields:
  copilot:
    type: copilot
    field: blocks
    help: |
      Example: Write a summary of this page and include the contents of {blocks}.
```
