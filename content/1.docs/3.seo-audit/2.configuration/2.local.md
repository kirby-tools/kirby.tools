Add Kirby SEO Audit to a Panel view as a **view button** (recommended) or a **field**. Both share their configuration properties and can be used together.

## View Button Configuration

Add the `seo-audit` view button to a site or page blueprint, alongside default buttons such as `preview` and `settings`. The analysis needs an HTML preview URL, so file views are out of scope.

::::panel-mock
:::panel-view-header
---

buttons:
  - plugin: seo-audit
    rating:
      seo: ok
      timestamp: 1788252000000
  - status: listed
---
:::
::::

Clicking the **SEO Audit** view button runs the analysis for the current page and opens the report in a dialog. The dot on the button is the page's [rating](/docs/seo-audit/guide/ratings).

### Basic Setup

To add the `seo-audit` view button to a Panel view, set the `buttons` option in the corresponding blueprint. Listing `buttons` replaces Kirby's defaults, so name the ones you want to keep – the default set differs per model. `seo-audit` goes wherever it suits the view:

::code-group

```yaml [site.yml]
buttons:
  - seo-audit
  - open
  - preview
  - languages
```

```yaml [pages/default.yml]
buttons:
  - seo-audit
  - open
  - preview
  - settings
  - languages
  - status
```

::

### Add the Button to Every View

To add the button to the site view and every page view without editing each blueprint, set Kirby's `panel.viewButtons` option. It replaces the defaults the same way a blueprint list does, and a blueprint that sets `buttons` wins over it:

```php [site/config/config.php]
return [
    'panel' => [
        'viewButtons' => [
            'site' => ['seo-audit', 'open', 'preview', 'languages'],
            'page' => ['seo-audit', 'open', 'preview', 'settings', 'languages', 'status']
        ]
    ]
];
```

To pass props such as `keyphraseField`, give `seo-audit` a key and keep the other buttons as plain names: `'seo-audit' => ['keyphraseField' => 'metaKeyphrase']`. A query in `keyphrase` or `synonyms` resolves only in the blueprint.

### Pass Props to the Button

To pass properties, write `buttons` as an object. `seo-audit` takes the properties, and every other button you keep is set to `true`:

```yaml [pages/default.yml]
buttons:
  seo-audit:
    keyphraseField: metaKeyphrase
    assessments:
      - metaDescriptionKeyword
      - metaDescriptionLength
      - titleWidth
      - images
      - textLength
    contentSelector: "#main"
  open: true
  preview: true
  settings: true
  languages: true
  status: true
```

## Field Configuration

The SEO Audit field shows the report inline, among the page's fields, instead of in a dialog.

### Basic Setup

```yaml [pages/default.yml]
fields:
  seoAudit:
    type: seo-audit
```

## Shared Properties

Most snippets below show only the property line. Wrap them under `buttons.seo-audit` (view button) or under `fields.<name>` with `type: seo-audit` (field), as in the examples above.

Properties marked **Query** accept [Kirby's query language](https://getkirby.com/docs/guide/blueprints/query-language), so `{{ page.title }}` resolves against the current page. Single braces count as a query too, so `{ page.title }` resolves the same way and a literal `{…}` in the value is replaced – by nothing when the query finds nothing.

### `label` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

Custom label for the view button or the field. Both fall back to the plugin's own label in the current Panel language – "SEO Audit" in English.

```yaml
label: SEO Report
```

### `keyphraseField` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

Names the field of the current page that holds the keyphrase – the term the editor wants the page to rank for in Google.

```yaml [pages/default.yml]
buttons:
  seo-audit:
    # Reference the keyphrase field for the view button
    keyphraseField: metaKeyphrase

fields:
  # Define the keyphrase field
  metaKeyphrase:
    label: SEO Keyphrase
    type: text
    help: The keyphrase you want this page to rank for
  seoAudit:
    type: seo-audit
    # Reference the keyphrase field for the SEO Audit field
    keyphraseField: metaKeyphrase
```

While the page supplies no keyphrase from `keyphraseField` or [`keyphrase`](/docs/seo-audit/configuration/local#keyphrase), every keyphrase assessment is skipped, unless the `assessments` property lists it.

### `keyphrase` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"} :u-badge{label="Query" class="align-middle ml-2 rounded-full!" variant="subtle" color="neutral"}

Sets the keyphrase in the blueprint, so the editor does not enter one. Set alongside `keyphraseField`, it wins over the field's value.

```yaml
keyphrase: editorial design
```

A Kirby query resolves against the current page, so the keyphrase can follow the content:

```yaml
keyphrase: "{{ page.title.value }}"
```

### `synonymsField` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

Names the field of the current page that holds synonyms of the keyphrase, so the text does not have to repeat the keyphrase over and over.

```yaml [pages/default.yml]
buttons:
  seo-audit:
    synonymsField: metaSynonyms

fields:
  metaSynonyms:
    label: Keyphrase Synonyms
    type: tags
    help: Synonyms and variations of the keyphrase
  seoAudit:
    type: seo-audit
    synonymsField: metaSynonyms
```

### `synonyms` :u-badge{label="Array" class="align-middle ml-2 rounded-full!" variant="subtle"} :u-badge{label="Query" class="align-middle ml-2 rounded-full!" variant="subtle" color="neutral"}

Sets the synonyms in the blueprint, so the editor does not fill in a field. Like `keyphrase`, it wins over its field.

```yaml
keyphrase: editorial design
synonyms:
  - book design
  - typography
  - publication design
```

A Kirby query is only resolved in a string, and the result is split on commas. In list form every entry is used verbatim, so a `{{ }}` placeholder inside a list stays unresolved:

```yaml
synonyms: "{{ page.metaSynonyms }}"
```

### `assessments` :u-badge{label="Array" class="align-middle ml-2 rounded-full!" variant="subtle"}

Limits the report to the listed assessments; without it, all of them are enabled. The keys are listed in [Assessments for SEO and Readability](/docs/seo-audit/guide/assessments). With a single readability key in the list, Readability shows as "Not available".

```yaml
assessments:
  # Select the assessments you want to include
  - metaDescriptionKeyword
  - metaDescriptionLength
  - titleWidth
  - images
  - textLength
  - imageKeyphrase
```

### `contentSelector` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

A CSS selector for the part of the page to analyze. Use it to keep navigation, footers, or sidebars out of the analysis, so content that repeats on every page is not flagged.

**Default:** `body`

To analyze the content of one element only:

```yaml
contentSelector: "#main"
```

The selector scopes the plugin's [custom assessments](/docs/seo-audit/guide/assessments#custom-assessments) too, so an H1 outside the selected elements is reported as missing.

::note
The `contentSelector` also supports querying for multiple elements. For instance, to select all elements with the class `.seo-audit-allowed` while excluding elements with the class `.seo-audit-ignore`, you can use the following selector: `.seo-audit-allowed > *:not(.seo-audit-ignore)`.
::

To see the extracted HTML in the browser console, set `logLevel` to `info` or `debug`:

```yaml
contentSelector: ".seo-audit-allowed > *:not(.seo-audit-ignore)"
logLevel: info
```

### `links` :u-badge{label="Boolean" class="align-middle ml-2 rounded-full!" variant="subtle"}

The results link to articles on [Yoast.com](https://yoast.com) that explain each assessment. Set `links` to `false` to remove them – for privacy reasons, or to keep the editor in the Panel.

**Default:** `true`

```yaml
links: false
```

### `analyzeOn` :u-badge{label="String | Boolean" class="align-middle ml-2 rounded-full!" variant="subtle"}

Turns the [analysis after publishing](/docs/seo-audit/configuration/global#analyzeon) on with `publish` or off with `false` for this view button or field. A blueprint value overrides the global option.

```yaml
analyzeOn: publish
```

### `logLevel` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

Controls how much the plugin logs to the browser console during analysis. Available levels are `error`, `warn` (default), `info`, and `debug`. It can also be set [globally](/docs/seo-audit/configuration/global#loglevel); a blueprint value overrides it. An unknown level shows an error in place of the field.

```yaml
logLevel: info
```

## View Button-Only Properties

### `theme` :u-badge{label="String" class="align-middle ml-2 rounded-full!" variant="subtle"}

Sets the color theme of the button.

**Default:** `positive-icon`  
**Options:** Any theme Kirby's button component accepts, including the filled variants without the `-icon` suffix – see Kirby's [UI reference](https://getkirby.com/docs/reference/plugins/ui).

```yaml
buttons:
  seo-audit:
    theme: positive
```

## Field-Only Properties

### `persisted` :u-badge{label="Boolean" class="align-middle ml-2 rounded-full!" variant="subtle"}

By default, reports are saved to the browser's local storage, one per field, page, and language, so an editor can close the Panel and return later without rerunning the analysis. The [rating](/docs/seo-audit/guide/ratings) the plugin keeps on the server is unaffected by this property.

To stop saving the report:

```yaml [fields/seo-audit.yml]
type: seo-audit
persisted: false
```
