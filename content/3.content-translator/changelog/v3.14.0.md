date: 2026-08-21

**🚀 Features**

- **Runs report what they translated**: A run that leaves segments in the source language now says how many, instead of ending in a plain success message. The browser console names each one with its field and the reason. See [Translation Results](/docs/content-translator/panel/translation-results).
- **Two new drop reasons**: `empty translation` and `missing translation` join the reasons handed to the [`content-translator.translate:warning`](/docs/content-translator/advanced/hooks#drop-reasons) hook, which now fires in both cases. `placeholder count mismatch` is called `placeholder mismatch`.

**🐞 Bug Fixes**

- **No more false success messages**: Every run used to end in "Content translated", even when nothing had been touched. Imports too.
- **A dropped translation never empties a field**: A blank provider response leaves the field, and a tag list its entries, with the original content.
- **DeepL drops are visible**: A segment DeepL could not translate is reported instead of handed back as if it had been translated. Previously only AI translations surfaced one.
- **KirbyTags survive translation**: A stray space in the plugin's internal marker no longer discards the translation, and a translation that repeated one link while dropping another is now caught – it used to pass, because it carried the right number of markers.
- **A failed title no longer sinks the run**: The title is reported as untranslated instead of ending an otherwise successful run in an error dialog.
- **One failed language no longer sinks a batch run**: The languages already written stay written, the rest are still translated, and the run names the language it lost.
