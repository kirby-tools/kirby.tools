**🚀 Features**

- **Runs report what they translated**: A run that leaves segments in the source language now says how many, and the console names each one with its field and reason. A run whose provider fails outright is reported as an error instead. See [Translation Results](/docs/content-translator/panel/translation-results).
- **Drop reasons renamed and split**: `placeholder count mismatch` is now `placeholder mismatch`, and `empty or non-string translation` splits into `empty translation` and `non-string translation`. Both, plus `missing translation`, now reach the [`translate:warning`](/docs/content-translator/advanced/hooks#drop-reasons) hook. Update handlers matching the old strings.

**🐞 Bug Fixes**

- **No more false success messages in the Panel**: Runs and imports used to end in "Content translated" even when nothing was touched. Server-side callers still report through the warning hook, not a return value.
- **A dropped translation never empties a field**: A blank response leaves the field, and a tag list its entries, untouched. DeepL drops are reported instead of passed off as translations.
- **KirbyTags survive translation**: A stray space in the internal marker no longer discards the translation, and a translation that repeats one link while dropping another is now caught.
- **A failed title no longer sinks the run**: The title is reported as untranslated instead of ending the run in an error dialog.
- **One failed language no longer sinks a batch run**: Written languages stay written, the rest still translate, and the run names the one it lost.
