::tip
125 DeepL target languages now translate, and regional variants follow your Kirby language code – a `de-ch` page gets Swiss German even when the server's locale says `de_DE`.
::

**🚀 Features**

- **Full DeepL language catalogue**: Languages such as Catalan, Serbian, Swahili, Cantonese, and Welsh now translate instead of failing with an unsupported-language error. See the [DeepL documentation](/docs/content-translator/providers/deepl#supported-languages).
- **Language code overrides**: The new `targetLanguageOverrides` config option maps a Kirby language code to any DeepL target code – including codes DeepL releases after this version. See the [DeepL documentation](/docs/content-translator/providers/deepl#language-code-overrides).

**🐞 Bug Fixes**

- **Regional variants follow the language code**: A `de-ch` language now translates to Swiss German and `zh-tw` to Traditional Chinese, even when the server locale disagrees. Previously the locale won, so sites with both a Simplified and a Traditional language received identical translations for the two. Thanks to [@gutschik](https://github.com/gutschik) for the report.
- **Custom strategies in the Panel**: A `strategy` closure or `Strategy` instance now enables the translation buttons on its own and is labelled `Custom` in the provider dialog. Previously the Panel only recognized a `DeepL.apiKey` and offered `DeepL` regardless of the configured backend.
- **Plugin options stay on the server**: The Panel receives only the options it uses. A custom `Strategy` instance's properties – API keys included – are no longer part of the Panel payload.
- **Import without a translation provider**: Import actions stay available when no translation backend is configured – copying content between languages never required one.

**⚠️ Behavior Changes**

- **`requestOptions` no longer override languages**: `source_lang` and `target_lang` set in `requestOptions` are ignored – the resolved languages always win. Use `targetLanguageOverrides` to pin a target code.
